# PayFlow v0.6.0

Esta versão inicia o M5.2 com uma cadeia de imagens imutáveis. API e front-end passam a poder ser
construídos uma única vez no GitHub Actions, armazenados no Amazon ECR e identificados pelos digests
que serão usados na promoção entre ambientes.

## Destaques

- ADR-0026 definindo build único, promoção por digest e rollback;
- repositórios persistentes `payflow-api` e `payflow-frontend` no Amazon ECR;
- tags imutáveis, criptografia AES-256, scan no push e lifecycle para imagens sem tag;
- autenticação do GitHub Actions na AWS por OIDC, sem access keys persistentes;
- role de publicação limitada aos dois repositórios e policy de runtime somente leitura;
- workflow manual que exige CI verde no commit exato e reutiliza imagens existentes;
- tag de imagem `git-<SHA completo>` e manifesto JSON com os dois digests;
- testes automatizados das revisões autorizadas para construção.

## Fluxo da candidata

1. a candidata nasce na branch `release/0.6.0` a partir do M5.2.1 e M5.2.2 integrados em `develop`;
2. Maven, projeto raiz, front-end e lockfiles declaram a versão `0.6.0`;
3. a CI valida código, Compose, Terraform, política de revisão, E2E e Quality Gate;
4. a candidata pode ser publicada temporariamente em homologação pelo deploy atual;
5. promover a candidata por Pull Request para `main` após aprovação;
6. criar a tag anotada `v0.6.0` e o GitHub Release somente depois dos checks em `main`;
7. executar `Build Immutable Images` para `v0.6.0` e registrar os primeiros digests no ECR.

## Bootstrap do workflow manual

O GitHub registra workflows de `workflow_dispatch` a partir da branch padrão. Como esta é a versão que
introduz `build-immutable-images.yml`, a primeira execução acontece depois que o workflow chega à
`main`. A partir da próxima release, o mesmo workflow já poderá construir `release/X.Y.Z` antes da
promoção, permitindo que produção reutilize exatamente os digests aceitos em homologação.

## Limites desta versão

- o Compose de produção ainda possui `build:` e a EC2 ainda compila as imagens durante o deploy;
- a policy de leitura do ECR ainda não está ligada à role da EC2;
- o manifesto é guardado como artifact da execução por 90 dias;
- rollback, logs centralizados, HTTPS com domínio e RDS permanecem em incrementos posteriores.

## Executar localmente

O ciclo local não depende do ECR:

```bash
docker compose up --build
```

Abra <http://localhost:5173>. A documentação da API fica em
<http://localhost:8080/swagger-ui.html> e as métricas internas em
<http://localhost:8080/actuator/metrics>.

## Aviso

O PayFlow é um projeto de portfólio. Todas as contas e quantias são fictícias e nenhuma operação
movimenta dinheiro real.
